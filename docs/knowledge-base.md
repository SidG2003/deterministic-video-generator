# Knowledge base for generated Manim code

Goal: help the LLM produce code that runs, reads cleanly and looks good, without
making every video look the same. Built in layers; each is measured with the run
logs (success, attempts, tokens, overlaps) before the next is added.

## Sources and how each is used
| Source | Version / license | Used as |
|---|---|---|
| Installed ManimCE package (`manim` 0.21.0, pinned) | exact runtime version; MIT | **API reference** (generated by introspection) and **static checks** |
| ManimCE docstring examples (397 in the installed package) | same version; MIT | test set for the checker today; candidate **technique snippets** later |
| Our own runs that render cleanly (0 detector issues, rated good) | ours | candidate **technique snippets** later |
| 3Blue1Brown video code (`3b1b/videos`) | written for **manimgl**, not ManimCE; **CC BY-NC-SA 4.0** | **reference only**: design ideas (staging, pacing, colour meaning) rewritten in our own words. No code copied into prompts or the repo — the API differs (`ShowCreation`, `self.frame`, …) and the license is non-commercial/share-alike. |

Why not docs or web examples for the API: they mix versions (and manimgl syntax).
Introspecting the installed package can't drift, and regenerates if Manim is upgraded.

## Layer 1 — API reference + static check (built)
- `dvg/kb/api.py` reads the installed package: 587 exported names, 258 classes
  (constructor params across the MRO, members), and the attributes of real scene
  and camera instances (some only exist after construction: `self.camera.frame`
  only on MovingCameraScene; `add_fixed_in_frame_mobjects` only on ThreeDScene).
  `python -m dvg.kb.api Arrow Text` prints a class's reference.
- `dvg/kb/check.py` (`api-check-v1`) checks generated code **before it runs**.
  Error rules fire only when the crash is certain: undefined names, missing scene
  or camera attributes, GrowArrow on a non-Arrow, helpers called with arguments
  their definition doesn't accept (incl. helpers nested in `construct`), and
  methods a Manim class doesn't have (dynamic `get_*`/`set_*` are skipped).
  Constructor keywords are advisory only (Manim forwards `**kwargs` deeply).
- In freeform and cold-sim it runs as the `api_check` step after the security
  scan; errors skip the render and go to the repair loop, all at once. Findings
  are logged per attempt in `meta.json` as `api_checks`.
- Validation:
  - Code that actually ran (31 files from past runs): **0 false alarms**.
  - ManimCE docstring examples: 7 of 395 flagged, all correct for our setup
    (6 use OpenGL classes that `from manim import *` doesn't provide, 1 uses
    `Any` without importing it). The keyword rule misfires on valid examples
    (`tip_shape`, `path_arc`), which is why it is advisory.
  - Past crashing attempts: the exact crash found beforehand in 7 of 11; the file
    identified as broken in 10 of 11 (in 3, a later certain crash was found
    after an earlier geometry error). Missed: runtime geometry errors (arc radius,
    Brace/zip), which static checks can't see.

The API reference affects correctness only, not the look: it never shows the
model example scenes.

## Layer 2 — technique snippets (not built; build only if measured need)
Risk: examples make videos look engineered/templated. Mitigations to apply:
- Snippets are **technique-level** (how to call things, 10–30 lines), never whole
  scenes or compositions.
- Retrieved only when a scene needs that technique; several varied snippets per
  technique; rotate them.
- Labelled in the prompt as API usage references — "design your own composition".
- Measure copying: code similarity between generated scenes and the snippets,
  plus visual review of variety across videos.
- Every snippet must render and score clean on the overlap detector.

## Layer 3 — layout helpers and design recipes (not built)
- Layout helpers the model calls (`title_band`, `caption`, `label`,
  `clear_section`) — overlap-safe by construction.
- Design recipes inspired by 3b1b (in our words), each paired with a checked
  ManimCE snippet.

## Versioning
Each layer is versioned (`api-check-v1`, prompt tags, `overlap-v1`) and logged
in every run, so changes can be compared on the same metrics.
